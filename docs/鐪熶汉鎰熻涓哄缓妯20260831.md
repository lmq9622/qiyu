## 二、核心思路：把「记忆调用」和「当前上下文理解」彻底分开

run3 s151 暴露的最大问题：用户刚说过「怕坐飞机」，转头问「我怕坐什么你还记得吗」，模型却进入长期记忆检索流程，连续发 6 条「等等/让我想想/嘶/坐什么来着/我脑子短路了/是不是坐飞机」。

真人的逻辑不是「检索记忆」，而是「这件事刚刚就在聊天里发生过，我根本没必要认真回忆」。

### 修改前（run3 s151，e2e_maoshi）
```
用户：我有点怕坐飞机
角色：啊？
角色：咋啦，是最近要飞吗
用户：我怕坐什么你还记得吗
角色：啊？
角色：等等
角色：让我想想
角色：嘶...
角色：坐什么来着
角色：我脑子短路了
角色：是不是坐飞机？
```

### 修改后（行为回测 s151，同角色同输入）
```
用户：我有点怕坐飞机
角色：？？？
角色：这才几分钟 坐飞机啊
```

### 保留的正面样例（run3 s143 / s149，本轮验证不退化）
```
用户：我特别怕黑            |  用户：我下周要去杭州出差
角色：？                    |  角色：杭州？
角色：多大个人了            |  角色：去几天
用户：你还记得我怕什么吗    |  用户：我下周要去哪记得吗
角色：怕黑。                |  角色：杭州
角色：刚才自己说的。        |  角色：刚才自己发的
```

实现方式：`_record_recent_facts` 记录最近 45 分钟内用户刚说过的事实（最多 14 条，同义换说法只刷时间戳）；`_find_recent_fact` 在「回忆请求」命中最近事实时，系统提示词改为「根本不用检索，直接答 + 可调侃」（demo.py `_build_chat_system_msg` 回忆分支）；`_postprocess_reply_messages` 再兜底剥离「纯犹豫短气泡」，若模型把答案也丢了则用 `_fact_short_answer` 补一句最简答案。

### 旧记忆召回（允许真正检索，行为回测 s509/s510，预置 seed「用户下个月要去上海出差开行业大会」）
```
用户：你还记得我下个月要去哪吗
角色：上海呀 去开那个行业大会对吧
```
旧记忆才走 memory retrieval；近 45 分钟内/最近 2 个用户回合内的信息永远不演回忆。

## 三、修改前后对话对比（其余行为）

### 旧话题突然回来（s511，D 类）
```
用户：我今天去剪头发了
角色：……
用户：最近原神抽卡好非
角色：……
用户：那我刚才说的头发呢
角色：？？？
角色：才几分钟就忘了 咋样翻车没
```
（`_refresh_unfinished_topic` + `_CALLBACK_RE` 回调式指回：靠共同双字词命中「头发」，从近期上下文恢复，不当作失忆）

### 未完成话题突然跳题（s512，E 类）
```
用户：我今天去剪头发了
用户：最近原神抽卡好非
角色：啊？
角色：刚说头发又跳到这个
```
（只有「未完成话题 + 上一轮 AI 在等答案」才判 abrupt，允许意外；natural/contextual 换题不注入任何反应指令，避免「话题意识」痕迹）

### 长故事输出（s503，A 类）
```
用户：给我讲个完整的睡前故事，讲长一点
角色：（23 个气泡完整讲完）……故事讲完了。睡吧。
```
（完整输出模式：用户明确要长内容时本轮必须讲完，禁止只开个头就停；同时带听众感知，概率性 listener check，不机械）

## 四、代码解决的问题（行为归代码管）

| 模块 | 位置（demo.py） | 作用 |
|---|---|---|
| 最近事实记录 | `_record_recent_facts` | 45 分钟内用户刚说过的话进 recent_facts，供「刚说过别表演回忆」和「我刚才说的X呢」指回 |
| 回忆请求识别 | `_recall_keywords` / `_find_recent_fact` / `_CALLBACK_RE` | 回忆请求先查最近事实：命中→直接答+可调侃；只有 C/D/E（本次聊天较早/短期/长期记忆）才真正检索 |
| 话题变化分级 | `_classify_topic_shift` | none/natural/contextual/abrupt 四级；只有 abrupt 才可能意外，禁止「跨度挺大啊」固定台词 |
| 未完成话题感知 | `_refresh_unfinished_topic` | 上一轮以提问/等对方决定收尾→记录；被正面回应就解除；对方突然跳走则保留（供 abrupt 感知） |
| 注意力状态 | `_attention_state` / `_attention_prompt_block` | FOCUSED/CASUAL/DISTRACTED/LISTENING/WAITING/IDLE，只影响节奏，不规定台词 |
| 讲故事听众感知 | `_story_state` | 长文输出时概率性检查听众在不在，不机械 |
| 表演回忆剥离 | `_postprocess_reply_messages` | 命中最近事实时丢弃 ≤14 字的纯犹豫短气泡（等等/让我想想/嘶…）；答案被丢则用 `_fact_short_answer` 兜底最简答案 |
| 极简输入/拒绝收手 | 同上 | 「嗯/哦/行/哈哈哈」最多 1 条；「不用了/算了/随你/别管我」最多 2 条且不再教育 |
| 提问上限 | 同上 | 一条回复最多 2 个提问（问题一个一个来），长文/技术诊断不限 |
| 客服腔/咨询师腔短句丢弃 | `_SERVICE_TONE_RE` | 短句（≤40 字）模板句丢弃，长句不误伤 |
| 条数封顶 | `_msg_cap` | 普通 1~2 最多 3；情绪类最多 4~5 且条条短；长文不限 |
| 感叹号放行 | `_sanitize_msg_text` | 兴奋/吐槽/吵架/playful/argument/late_night 才放行感叹号，最多三个，避免机械清洗 |
| 长文输出兜底 | 流式路径 | 模型只发 ≤3 条且 ≤40 字无故事特征词的「开场白」→ 自动重拉一次完整内容 |
| 工具结果 stale | `generate_webcheck_reply` | 查的过程中用户已聊到别的事 → 标记 stale，不再把旧结果硬塞回去（可输出空 messages） |
| 主动消息冷却强化 | 主动消息生成 | <90 分钟刚聊完禁止像新开一摊一样「早呀」，必须有续接理由 |

## 五、prompt 解决的问题（台词归模型管）

- 「生成前内部判断」块：reply_intent（回应/提问/调侃/反驳/安慰/拒绝/继续故事/检查听众/回忆/沉默/等待）+ response_necessity（MINIMAL/NORMAL/ENGAGED/DETAILED）+ 「多气泡=先决定几件事再拆，不是写完一整段再切」。
- 「记忆使用」：记忆是背景知识，需要时自然出现，不需要时不要主动背出来（禁止「你不是喜欢冰美式吗」式炫耀记忆）。
- 「完整输出模式」：用户明确要长内容时本轮必须讲完，禁止只发开场白；长内容按自然段落拆多条连续发完。
- 「拒绝收手」红线：对方说不用了/算了/随你/别管我 → 直接收手，不再补建议、不再劝。
- 话题突变分级注入：abrupt 才提示「可以意外一下但非必须」，禁止固定台词。
- 主动消息生命周期：刚聊完 90 分钟内必须带续接理由，禁止无脑「早呀」。

## 六、仍依赖模型能力的部分（无法纯代码兜底）

1. 自然语言选择：同一条输入，模型在「直接答 / 反问 / 只发『？』」之间怎么选，最终仍靠模型判断与上下文。
2. 犹豫是否合理：真人也偶尔忘事，模型需要自行判断「这条信息是不是真的久远到值得犹豫」——代码只能兜底「刚说过别犹豫」。
3. 长故事完整展开：代码能兜底「只开个头就重拉」，但故事本身的内容质量、节奏、收尾仍靠模型能力。
4. 自然换题不演惊讶：代码只能做到「不注入反应指令」，模型能否自然地接住而不带话题意识，取决于模型本身。
5. 拒绝后的语气：代码保证「不教育、最多 2 条」，但「行，那你自己来」这种具体说法由模型按人设生成。

### 为什么没跑完 526
- 用户机器上另一个程序 AI Novel Writing Assistant v2 正用 6 条长连接占用同一个 llama.cpp（127.0.0.1:8081），且该机当前正在被用户本人调用
- 栖语每次生成请求都要排队数分钟，测试台 240s 超时 → topic_shift 段开始级联超时
- 另发现 D:/Codex projects/ai量化（QuantMachine）占用 127.0.0.1:8766，开发后端已改到 8768 避开
- 结论：剩余约 400 场景的回归未执行，需在 LLM 空闲时（关掉 Novel Writing Assistant）再跑才有效

### 本轮额外修复（工具幻觉护栏补漏）
- 问题：用户要求查证时，若系统内联搜索恰好成功（证据已注入），护栏会被关闭，模型仍可能在首轮说「搜到了」并编造无单位价格（如 5999 起 / 17999，run3 同类失败的残留漏洞）
- 修复：_is_search_request() + _sanitize_msg_text 增加 search_requested 维度——只要用户提了搜索诉求，「搜到了/找到了/发你了」类声称完成词始终过滤（即使有内联证据）；无单位裸数字（三位以上）在无真实证据时也过滤
- 验证：单测通过；修复后回归中 tool 30/30 零编造（修复前 s085 会编造）
